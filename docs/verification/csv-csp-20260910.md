# CSV and CSP repair — 2026-09-10

Production error_log confirmed that PHP's deprecated default `fputcsv` escape
argument was converted to an exception by the API's strict error handler.
The previous isolated-controller export probe omitted that handler and therefore
did not reproduce the browser's HTTP 500. The revised probe dispatches the export
through Router with the same warning-to-exception policy. Authentication is stubbed
only inside a temporary secret-protected diagnostic; this is not a browser login test.

SMS, contact, wallet and report CSV writers now explicitly use `escape: ''`.
Campaign ownership checks, column selection, formula protection and message queries
are unchanged. The campaign export probe compares CSV rows, states, segments and
charges with the specific campaign's message records without exposing recipients.

The login bootstrap now lives in a same-origin external script. The CSP keeps
`script-src 'self'`; only the existing Google Fonts stylesheet and font hosts were
added to their respective directives.

DLR inspection still found 28 submitted messages and zero provider events. No
message was marked Delivered or Failed without a delivery receipt; no SMS was resent
and no credits were changed. Provider escalation remains necessary as documented in
`../integrations/logicsms-dlr-investigation.md`.

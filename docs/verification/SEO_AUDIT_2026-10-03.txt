IEOSUIA SMS PORTAL: TECHNICAL AND SEMANTIC SEO AUDIT
Production: https://sms.ieosuia.com/
Release verified: 3 October 2026, Africa/Johannesburg
Final assets: index-sFnpEv6n.js and index-DqIpjsql.css

EXECUTIVE RESULT
Implemented and deployed a scoped public SEO release. All 16 canonical public
pages return meaningful HTML without JavaScript. Local and live validation passed
for metadata, responsive layout, structured-data parsing, canonical URLs, internal
links, sitemap, public images and protected API access. Six useful public guides
were added without repurposing private campaign routes or creating industry
doorway pages. The approved homepage positioning and hero are preserved.

No API, PHP, database, payment, messaging, scheduler, opt-out or customer-record
changes were deployed. Existing account-route guards and central-auth destinations
are retained. Authenticated page code is loaded separately for performance.
The unrelated changes already present in the main checkout were not deployed.

1. PAGES CREATED OR CHANGED
New: /features, /use-cases, /contact-management, /scheduled-sms,
/delivery-reports and /faq.
Existing public pages improved: /, /pricing, /documentation, /support, /contact,
/careers, /privacy-policy, /terms-of-service, /cookie-policy, /popia-compliance.
The latter legal/careers/contact pages mainly received metadata, static rendering,
breadcrumbs and accessibility improvements; their existing policy/job claims were
not independently certified or rewritten as legal advice.

Pricing now describes the actual prepaid SMS model instead of unsupported
subscription tiers and active email pricing. Documentation describes the real SMS
workflow instead of advertising unavailable features. A support form previously
simulated a successful send without submitting an enquiry. It was replaced with
useful help and a link to the existing working contact form.
Email Campaigns remain Coming Soon. The functioning contact form was preserved.

6. ROBOTS.TXT
Public content, required CSS/JS and images remain crawlable.
Existing private/API/auth exclusions retained; internal public snapshot directory
excluded to discourage crawling implementation URLs.
Sitemap: https://sms.ieosuia.com/sitemap.xml

Robots.txt is not access control. Its disallow rules can also prevent crawlers from
seeing a page's noindex; if private URL-only listings already exist, use Search
Console removal tools and review crawl/noindex policy rather than expecting
robots.txt alone to deindex them.

16. REMAINING LIMITS AND FOLLOW-UP WORK
- Google Search Console and Bing ownership verification/sitemap submission need
  the owner's real tokens or DNS access. Nothing was fabricated or submitted.
- Actual indexing, ranking, social-platform cache refresh and external rich-result
  eligibility are not proven by these technical tests.
- Field LCP/CLS/INP remain unmeasured. Collect sufficient real-user data.
- Hosting response time is variable. Consider hosting/CDN investigation based on
  repeated measurements, not a single score.
- Approved high-resolution PNG logos and remaining public JavaScript/CSS provide
  further optimization scope. Any logo-asset change needs to respect approved usage.
- React still mounts the interactive application over the public snapshot. A future
  genuine SSR/hydration architecture may reduce repeat render work, but was not
  introduced here because it would require broader auth/rendering regression work.
  A local hydrateRoot trial against browser-generated snapshots produced React
  hydration errors. It was rejected and reverted, never deployed. A proper initial
  server-rendered tree is required; suppressing hydration errors is not a fix.
- Existing legal text, dates and careers opportunities need owner review for
  factual currency. No legal-compliance guarantee or job authenticity was invented.
- Existing hosting configuration emits some duplicate security headers. The strict
  CSP remained active; host-level header consolidation was outside this scoped
  release and should be tested separately.
- TypeScript and the production build passed. The existing lint command hit a
  dependency filesystem read error; Vitest workers timed out before running tests.
  Those suites are NOT claimed as passing. The dedicated browser/SEO checks above
  did run and pass. This was not an end-to-end payment/SMS business regression test.
- If any private URLs are already indexed, review removal/noindex crawlability in
  Search Console; blocking crawling and requesting deindexing are different actions.
